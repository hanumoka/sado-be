## 2. 멀티모듈 구성

### 2.1 공통 모듈 (Common Module)
- **타입**: Non-API 라이브러리 모듈
- **역할**: 다른 API 모듈들이 공통으로 사용하는 기능 제공
- **포함 기능**:
  - 공통 유틸리티
  - 공통 DTO/VO
  - 공통 예외 처리
  - 공통 상수 정의
  - 이벤트 스키마 정의

### 2.2 MiniPACS 모듈 (Server Module)
- **타입**: API 서버 모듈
- **주요 기능**:
  - **DICOM 파일 업로드 및 관리**: 심장 초음파 DICOM 파일 처리
  - **파일 스토리지**: SeaweedFS 기반 파일 관리
  - **S3 호환성**: 추후 S3 전환을 대비한 추상화 설계
  - **이벤트 발행**: Study 단위 업로드 완료 이벤트 발행
- **기술 스택**:
  - SeaweedFS (Object Storage)
  - DICOM 라이브러리 (dcm4che 등)

### ~~2.3 Auth 모듈 (API Module)~~ ❌ 최종 계획에서 제외

> ⚠️ **변경사항**: Auth 모듈은 최종 계획에서 제거되었습니다.
> Gateway에서 Keycloak을 직접 연동합니다.
> 자세한 내용은 `07_최종_구현_계획.md` 참조.

- **타입**: API 서버 모듈
- **주요 기능**:
  - 인증(Authentication) 처리
  - 인가(Authorization) 처리
  - 사용자 관리
  - 토큰 발급 및 검증
- **기술 스택**:
  - **Keycloak**: 오픈소스 IAM 솔루션

### 2.4 Gateway 모듈 (Entry Point)
- **타입**: API Gateway
- **주요 기능**:
  - 단일 진입점 (Single Entry Point)
  - 라우팅 및 로드 밸런싱
  - 인증/인가 필터링
  - Rate Limiting
  - CORS 처리
- **기술 스택**:
  - Spring Cloud Gateway

### 2.5 BFF 모듈 (Backend For Frontend)
- **타입**: 핵심 서비스 모듈
- **주요 기능**:
  - 이벤트 컨슈밍 (MiniPACS에서 발행한 이벤트)
  - Triton 서버 연동 (AI 분석 요청)
  - 분석 결과 데이터 저장
  - 리포트 생성
  - 프론트엔드를 위한 API 제공
- **역할**:
  - 여러 마이크로서비스 조합
  - 프론트엔드 친화적 API 제공
  - 비즈니스 로직 오케스트레이션

## 3. 예상 동작 시나리오

### 3.1 DICOM 파일 업로드 및 분석 플로우

```
1. DICOM 파일 업로드
   Client → Gateway → MiniPACS
   └─> SeaweedFS에 파일 저장
   └─> Study 단위로 업로드 완료 확인
   └─> 이벤트 발행: "Study Upload Completed" (Event A)

2. AI 분석 요청
   Event A → BFF (Consumer)
   └─> Triton 서버에 Study 단위 분석 요청 (Event B)

3. AI 분석 처리
   Event B → Triton 서버 (sado-ai)
   └─> DICOM 파일 분석
   └─> 데이터 가공 및 결과 생성
   └─> 분석 완료 이벤트 발행

4. 분석 결과 처리 및 리포트 생성
   Triton 분석 결과 → BFF
   └─> 분석 데이터 저장
   └─> 리포트 생성
   └─> 프론트엔드에 결과 제공
```

### 3.2 이벤트 플로우
- **Event A**: `StudyUploadCompletedEvent`
  - Publisher: MiniPACS
  - Consumer: BFF

- **Event B**: `StudyAnalysisRequestEvent`
  - Publisher: BFF
  - Consumer: Triton Server (sado-ai)

- **Event C**: `StudyAnalysisCompletedEvent`
  - Publisher: Triton Server
  - Consumer: BFF

## 4. 학습 목표 및 적용 기술

### 4.1 오픈소스 기술
| 기술 | 용도 | 적용 모듈 |
|------|------|-----------|
| **Keycloak** | 인증/인가 (IAM) | Auth 모듈 |
| **Temporal** | 워크플로우 오케스트레이션 | BFF, MiniPACS |
| **SeaweedFS** | 분산 파일 스토리지 | MiniPACS |

### 4.2 인프라 기술
| 기술 | 용도 | 적용 모듈 |
|------|------|-----------|
| **Redis (Redisson)** | 캐싱, 분산락 | 공통, BFF |
| **Debezium** | CDC (Change Data Capture) | 검토 필요 |

### 4.3 아키텍처 패턴
- **EDA (Event-Driven Architecture)**: 이벤트 기반 모듈 간 통신
- **분산락**: Redis 기반 동시성 제어
- **분산 트랜잭션**: Saga 패턴 (Temporal 활용 가능)
- **MSA (Microservices Architecture)**: 멀티모듈 기반 서비스 분리
