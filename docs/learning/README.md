## 📏 작성 원칙

### DO ✅
- **구체적으로 작성**: "Kafka를 배웠다" ❌ → "Kafka의 Partition 전략 3가지를 학습하고 직접 구현했다" ✅
- **코드 스니펫 포함**: 핵심 코드는 간단히 포함 (전체 코드는 Git 커밋 참조)
- **에러 기록**: 겪었던 에러와 해결 방법 상세히 기록
- **인사이트 기록**: "아하!" 모먼트를 놓치지 말기
- **시간 기록**: 실제 학습 시간 기록 (회고 시 유용)

### DON'T ❌
- **복사-붙여넣기 금지**: 공식 문서를 그대로 복사하지 말 것 (자신의 언어로 재정리)
- **코드 전체 복사 금지**: 핵심 스니펫만 (전체 코드는 Git 참조)
- **형식적 작성 금지**: "배웠다", "이해했다"로 끝내지 말고 구체적으로

## 💡 활용 방법

### 1. 복습
- 다음 Phase 시작 전 이전 Phase 회고 읽기
- 막힐 때 이전 학습 노트 참조

### 2. 포트폴리오
- GitHub README에 학습 과정 요약
- 블로그 포스팅 자료로 활용

### 3. 면접 준비
- "프로젝트에서 어려웠던 점" 질문 대비
- "어떻게 해결했는지" 구체적 사례 제시

### 4. 지식 베이스
- 개인 Notion/Obsidian으로 이동
- 다음 프로젝트에서 참조
