## 1. 최종 멀티모듈 구조

### 1.1 권장 모듈 구조

```
sado-be/
│
├── sado-common/                    # 공통 모듈 (3개 하위 모듈)
│   ├── common-core/               # 핵심 공통 기능
│   │   ├── utils/                # 유틸리티 클래스
│   │   ├── dto/                  # 공통 DTO
│   │   └── exception/            # 공통 예외 클래스
│   │
│   ├── common-event/              # 이벤트 스키마 (버전 관리)
│   │   ├── BaseEvent.java       # 이벤트 기본 클래스
│   │   └── events/              # 이벤트 정의 (V1, V2...)
│   │
│   └── common-security/           # 공통 보안 설정
│       ├── JwtUtil.java
│       └── SecurityConfig.java
│
├── sado-infrastructure/           # ⭐ 인프라 모듈 (새로 추가)
│   ├── kafka-config/             # Kafka Producer/Consumer 설정
│   ├── redis-config/             # RedissonClient 설정
│   ├── temporal-config/          # Temporal Worker 설정
│   └── storage-config/           # SeaweedFS/S3 클라이언트 설정
│
├── sado-gateway/                  # API Gateway
│   ├── filters/                  # Custom Filters (Auth, Rate Limiting)
│   └── config/                   # Gateway Configuration
│
├── sado-minipacs/                 # DICOM 파일 관리 서비스
│   ├── minipacs-api/            # REST API Layer
│   │   ├── controller/
│   │   └── dto/
│   │
│   ├── minipacs-domain/         # Domain Layer
│   │   ├── model/               # Domain Model (Study, Series, Instance)
│   │   ├── service/             # Business Logic
│   │   └── repository/          # JPA Repository
│   │
│   └── minipacs-storage/        # Infrastructure Layer
│       ├── SeaweedFsClient.java # SeaweedFS 연동
│       └── DicomParser.java     # DICOM 파일 파싱
│
├── sado-orchestrator/             # ⭐ 비즈니스 워크플로우 오케스트레이션 (BFF에서 분리)
│   ├── orchestrator-workflow/   # Temporal Workflow
│   │   ├── DicomAnalysisWorkflow.java
│   │   └── activities/          # Temporal Activities
│   │
│   └── orchestrator-api/        # Orchestrator REST API (내부 통신용)
│
└── sado-bff/                      # Backend For Frontend
    ├── bff-api/                  # 프론트엔드를 위한 API 조합
    │   ├── controller/          # GraphQL or REST Aggregation
    │   └── service/             # 여러 서비스 조합
    │
    └── bff-config/              # BFF 설정

참고:
- Auth 모듈은 Phase 1에서 제외
- Gateway에서 Keycloak 또는 JWT를 직접 연동
```

### 1.2 모듈 간 의존성

```
Gateway → MiniPACS, BFF, Orchestrator
MiniPACS → Common, Infrastructure (Kafka, Storage)
Orchestrator → Common, Infrastructure (Temporal, Kafka)
BFF → Common, Infrastructure (Redis)

모든 모듈 → Common-Core, Common-Event
```

### 1.3 모듈별 책임

| 모듈 | 책임 | 주요 기능 |
|------|------|-----------|
| **sado-gateway** | API 진입점, 라우팅, 인증 | 라우팅, JWT 검증, Rate Limiting |
| **sado-minipacs** | DICOM 파일 관리 | 업로드, 저장, 조회, 이벤트 발행 |
| **sado-orchestrator** | 비즈니스 워크플로우 | Temporal Saga, AI 연동, 보상 트랜잭션 |
| **sado-bff** | 프론트엔드 API 조합 | 여러 서비스 API 조합, 데이터 변환 |
| **sado-infrastructure** | 인프라 추상화 | Kafka, Redis, Temporal, Storage 설정 |
| **sado-common** | 공통 기능 | Utils, DTO, Events, Security |

## 2. 기술 스택 단계별 도입 전략

### 2.1 Phase 1 (POC - 4주): 핵심 플로우 동작

**목표:** DICOM 업로드 → 이벤트 발행 → Mock AI 분석 → 리포트 생성

#### 기술 스택
```

- Spring Boot 3.x (안정 버전 권장)
- Java 21
- Gradle 9.2.1

Database:
- PostgreSQL (JSONB, 복잡한 쿼리)

Messaging:
- Kafka (기본 Producer/Consumer)

API Gateway:
- Spring Cloud Gateway

Storage:
- 로컬 파일 시스템 (S3 호환 인터페이스 구현)
```

### 2.2 Phase 2 (Learning - 2-3주): Kafka 심화

**목표:** Kafka 이벤트 아키텍처 깊이 학습

2. **파티션 전략**
   - Study ID 기반 파티셔닝 (순서 보장)

   - 이벤트 버전 필드 추가
   - Consumer 하위 호환성 유지

4. **Outbox Pattern**
   - DB 트랜잭션 + 이벤트 발행 원자성
   - Outbox 테이블 폴링 및 Kafka 발행

5. **에러 핸들링**
   - 재시도 정책 (즉시, 지연, DLQ)
   - 멱등성 보장 (이벤트 ID 기반 중복 체크)

#### 프로젝트 적용
- Outbox Pattern 구현 (MiniPACS)
- DLQ 설정 및 모니터링
- 이벤트 버전 관리 (V1 → V2 마이그레이션 시뮬레이션)

### 2.3 Phase 3 (Learning - 2-3주): Temporal 심화

   - Workflow vs Activity
   - Temporal Server 아키텍처
   - Worker 구조

2. **Saga 패턴**
   - DICOM 분석 워크플로우 설계
   - 보상 트랜잭션 (Compensation)
   - Activity 재시도 정책

3. **장기 실행 작업 처리**
   - Timeout 설정
   - Async Activity 패턴
   - Polling vs Callback

4. **Temporal 모니터링**
   - Temporal Web UI 활용
   - Workflow 상태 추적
   - 실패 시나리오 디버깅

#### 프로젝트 적용
- Orchestrator 모듈에 Temporal 통합
- DicomAnalysisWorkflow 구현
  ```
  1. UploadDicomActivity (파일 저장)
  2. ValidateDicomActivity (DICOM 검증)
  3. RequestAnalysisActivity (Triton 연동)
  4. WaitForAnalysisActivity (결과 대기)
  5. SaveResultActivity (DB 저장)
  6. GenerateReportActivity (리포트 생성)
  ```
- 실패 시나리오 테스트 (Triton 응답 없음, 타임아웃 등)

### 5.1 Gradle 멀티모듈 설정

**`settings.gradle`**
```gradle
rootProject.name = 'sado-be'

// Common 모듈
```

### 5.3 PostgreSQL 스키마 (Phase 1)

```sql
-- Study 테이블
CREATE TABLE study (
    study_id VARCHAR(64) PRIMARY KEY,
    patient_id VARCHAR(64) NOT NULL,
    study_date DATE NOT NULL,
    modality VARCHAR(16) NOT NULL,
    study_description TEXT,
    status VARCHAR(20) NOT NULL, -- UPLOADED, ANALYZING, COMPLETED, FAILED
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    metadata JSONB -- DICOM 메타데이터 (JSONB)
);

-- Series 테이블
CREATE TABLE series (
    series_id VARCHAR(64) PRIMARY KEY,
    study_id VARCHAR(64) REFERENCES study(study_id),
    series_number INT,
    series_description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Instance (DICOM 파일) 테이블
CREATE TABLE instance (
    instance_id VARCHAR(64) PRIMARY KEY,
    series_id VARCHAR(64) REFERENCES series(series_id),
    instance_number INT,
    file_path VARCHAR(512) NOT NULL, -- SeaweedFS/로컬 FS 경로
    file_size BIGINT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Analysis Report 테이블
CREATE TABLE analysis_report (
    report_id VARCHAR(64) PRIMARY KEY,
    study_id VARCHAR(64) REFERENCES study(study_id),
    status VARCHAR(20) NOT NULL, -- PENDING, COMPLETED, FAILED
    analysis_result JSONB, -- AI 분석 결과
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Outbox 테이블 (Phase 2)
CREATE TABLE outbox (
    id BIGSERIAL PRIMARY KEY,
    event_id VARCHAR(64) UNIQUE NOT NULL,
    event_type VARCHAR(128) NOT NULL,
    payload JSONB NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    processed BOOLEAN DEFAULT FALSE
);

-- 처리된 이벤트 ID (멱등성 보장)
CREATE TABLE processed_event (
    event_id VARCHAR(64) PRIMARY KEY,
    processed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
