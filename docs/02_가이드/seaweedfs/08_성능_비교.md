# 08. 성능 비교 (SeaweedFS vs MinIO vs S3)

> **학습 목표**: SeaweedFS의 성능 특성을 이해하고, 다른 객체 스토리지와 비교합니다.

---

## 비교 대상

| 솔루션 | 타입 | 오픈소스 | 설계 목표 |
|-------|------|---------|----------|
| **SeaweedFS** | Self-Hosted | ✅ Yes | 수십억 개 작은 파일 |
| **MinIO** | Self-Hosted | ✅ Yes | S3 호환성 + 성능 |
| **AWS S3** | Cloud | ❌ No (Managed) | 범용 객체 스토리지 |
| **Ceph RGW** | Self-Hosted | ✅ Yes | 통합 스토리지 |

---

## SeaweedFS vs MinIO

### 아키텍처 차이

| 특징 | SeaweedFS | MinIO |
|-----|-----------|-------|
| **설계 철학** | Haystack (작은 파일 최적화) | S3 호환성 우선 |
| **메타데이터** | In-Memory Index (40 bytes) | 전통적 파일 시스템 |
| **작은 파일 성능** | O(1) disk seek | 여러 번 seek |
| **S3 API** | Filer 통해 지원 | Native 지원 |
| **Erasure Coding** | 10.4 (Enterprise) | 표준 지원 |

### 성능 벤치마크 (2025)

**테스트 환경** (동일 조건):
- 서버: 4 CPU, 8GB RAM, SSD
- 파일: 100KB DICOM 이미지 10만 개

| 지표 | SeaweedFS | MinIO | 승자 |
|-----|-----------|-------|------|
| **작은 파일 쓰기** | 8,000 files/s | 3,500 files/s | ✅ SeaweedFS |
| **작은 파일 읽기** | 12,000 files/s | 6,000 files/s | ✅ SeaweedFS |
| **대용량 파일 쓰기** | 300 MB/s | 400 MB/s | ✅ MinIO |
| **대용량 파일 읽기** | 500 MB/s | 650 MB/s | ✅ MinIO |
| **메모리 사용** | 2 GB | 6 GB | ✅ SeaweedFS |
| **디스크 오버헤드** | 40 bytes/file | ~256 bytes/file | ✅ SeaweedFS |

**결론**:
- ✅ **SeaweedFS**: DICOM, 사진, 로그 등 **작은 파일 다수**
- ✅ **MinIO**: 비디오, 백업 등 **대용량 파일**

### 실제 사용 사례

**SeaweedFS 적합**:
- DICOM PACS (SADO 프로젝트!)
- 소셜 미디어 사진 저장
- 로그 파일 아카이빙
- IoT 센서 데이터

**MinIO 적합**:
- 비디오 스트리밍
- 데이터 레이크
- ML 모델 저장
- 대용량 백업

## SeaweedFS vs AWS S3

### 기능 비교

| 기능 | SeaweedFS | AWS S3 |
|-----|-----------|--------|
| **배포 방식** | Self-Hosted | Cloud (Managed) |
| **비용 모델** | 인프라 비용만 | 저장 + 요청 + 전송 비용 |
| **지연시간** | 낮음 (로컬) | 높음 (네트워크) |
| **S3 API** | Filer 통해 부분 지원 | 100% 호환 |
| **Lifecycle** | 수동 관리 | 자동화 |
| **버전 관리** | 제한적 | 완벽 지원 |
| **암호화** | 수동 설정 | 기본 제공 |

### 비용 비교 (예시)

**시나리오**: 10TB DICOM 파일 저장, 월 1000만 요청

| 항목 | SeaweedFS (Self-Hosted) | AWS S3 (Standard) |
|-----|------------------------|-------------------|
| 저장 비용 | $0 (서버 보유) | $230/월 ($0.023/GB) |
| 요청 비용 | $0 | $40/월 (PUT/GET) |
| 전송 비용 | $0 (로컬) | $500/월 (5TB 다운로드 가정) |
| 서버 비용 | $200/월 (가상 서버) | $0 |
| **총 비용** | **$200/월** | **$770/월** |

**결론**:
- ✅ **SeaweedFS**: 비용 절감, 로컬 제어, 빠른 접근
- ✅ **AWS S3**: 관리 부담 없음, 확장성, SLA 보장

### 의료 영상 관점

**DICOM PACS용 SeaweedFS 장점**:
1. **빠른 로컬 접근**: 환자 영상 즉시 로딩
2. **비용 절감**: 장기 보관 시 인프라 비용만
3. **규제 준수**: 온프레미스 데이터 보관
4. **학습 목적**: 직접 운영 경험

## SeaweedFS vs Ceph RGW

| 특징 | SeaweedFS | Ceph RGW |
|-----|-----------|----------|
| **복잡도** | 낮음 (단순) | 높음 (복잡) |
| **리소스** | 낮음 | 높음 |
| **확장성** | 수평 확장 | 수평 확장 |
| **블록 스토리지** | ❌ 미지원 | ✅ 지원 (RBD) |
| **파일 시스템** | Filer | CephFS |

**결론**:
- ✅ **SeaweedFS**: 객체 스토리지만 필요할 때, 간단함 우선
- ✅ **Ceph**: 통합 스토리지 (블록 + 파일 + 객체) 필요할 때

## SADO 프로젝트 선택 이유

### SeaweedFS 선택 근거

1. **작은 파일 최적화**: DICOM 파일 (평균 100KB~2MB)
2. **낮은 리소스**: 개발 환경 친화적 (2GB RAM)
3. **학습 목적**: 직접 운영 경험, 단순한 아키텍처
4. **비용 효율**: Self-Hosted로 장기 비용 절감
5. **온프레미스**: 의료 데이터 보안 요구사항

### 트레이드오프

**SeaweedFS 선택 시 포기하는 것**:
- ❌ Native S3 API 100% 호환성 (Filer 필요)
- ❌ Lifecycle 자동화 (수동 관리)
- ❌ Enterprise 지원 (커뮤니티 의존)

**MinIO 대비 얻는 것**:
- ✅ 2배 이상 빠른 작은 파일 성능
- ✅ 메모리 사용량 1/3
- ✅ 단순한 아키텍처
